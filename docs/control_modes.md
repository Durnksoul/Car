# 串口静止与运动平衡模式

本功能复用设备已保存的姿态 PID 和直立零点，不覆盖现有调参结果，不会自动启动车辆。

## 先使用静止平衡

串口 115200、8N1，每条命令以 CR 或 LF 结束。上电后等待 IMU 初始化，扶正车辆。

```text
pid show
balance status
mode hold
mode status
```

`mode hold` 需要有效的直立零点、姿态 Kp>0、最新 IMU/编码器数据且车体在允许启动角度内。
缺少条件时拒绝启动，不会自动把手扶姿态重新当作零点。必要时在待机、扶正静止时执行原有的 `balance zero`。
姿态参数使用设备保存值；最近报告的 4 / 0.1 / 0 是已有实车基线，本次功能没有把该数值硬编码到固件。

HOLD 的目标速度、转向角速度均为零；平衡电机仍在工作，不是 PWM=0。
如果速度 PID 全零，会提示 drift correction inactive：此时保留原有直立能力，但不能承诺不漂移。
HOLD 是零速目标，不是位置锁定，也不保证推开后回到原位置。

## 运动模式

先在待机下完成速度外环整定；其输出为目标倾角，不是电机 PWM。速度 PID 全零时 `mode drive` 拒绝启动。
转向 PID 全零时允许直行，但拒绝非零转向目标。待机时可使用 `pid turn Kp Ki Kd` 设置转向环，数值必须实测。

```text
mode drive
move 50 0
```

`move` 的两个数分别是平均编码器计数/秒（cps）和目标偏航角速度（deg/s），不是百分比或 RPM。
正速度沿用现有编码器/速度环方向，正转向沿用 IMU 偏航轴定义；低速测试确认实际运动方向。
初始软件范围为 ±300 cps、±45 deg/s，超出范围或非有限数值会拒绝，不会刷新指令时限。

发送端需要至少每 200 ms（5 Hz）重复发送当前 `move`。500 ms 未收到有效 `move`，自动切回 HOLD，
目标按 300 cps/s 和 90 deg/s² 的斜率降到零，姿态平衡继续运行。串口/未来 BLE 共用该命令入口。
HOLD 不需要心跳。超时后要继续运动，需重新 `mode drive`，旧的 `move` 不能启动电机。
这些限制是初始软件设置，并非实测的车速、载荷或机械额定值。

```text
mode hold
```

运动中发送它会平滑回到零速目标，不切断电机，不重置姿态/速度/转向 PID 的内部状态。
切入 DRIVE 时初始请求仍为零，要收到 `move` 才改变目标。

```text
standby
```

这条命令关闭电机驱动、清除运动目标，车辆失去主动平衡，需要扶住。倾倒、传感器过期/无效和驱动故障仍按原有逻辑停机。
故障后恢复传感器或收到 `move` 不会自行启动，需扶正后明确发送 `mode hold` 或 `mode drive`。

## 与调参软件互斥

成功执行 `mode hold/drive` 后，模式控制会拒绝调参软件的 SET、SETPOINT 和 RESET；待机后该限制仍保留，
防止残留的调参命令自动重新启动。恢复调参入口需明确执行：

```text
standby
mode tune
```

`mode tune` 本身不会启动电机；随后调参软件的自动启动规则沿用原有设置。
原有手动百分比控制也需先退出模式所有权（standby、mode tune），避免绕过模式启动条件。
上电恢复的只有参数和零点，模式、运动指令及启动状态不会恢复。

## 当前验证边界

本次先交付串口模式和已有命令入口复用，未启用 BLE 或制作手机应用。
软件会报告运行模式、请求目标、斜率处理后的实际目标，以及速度/转向环是否有增益。
实际静止漂移、目标速度跟踪、转向方向和断连减速距离仍需实车验证；不自动生成未经验证的外环 PID 参数。

## 减少刷屏：输入命令和周期状态分开

启动默认 `telemetry slow`，每秒显示一行可读状态，字段包括模式、平衡状态、相对倾角/角速度、两轮速度与指令 PWM。
IMU 无效或过期会明确显示 imu_valid=0。

```text
telemetry off
mode hold
mode status
telemetry slow
```

`off` 只关闭周期数据；命令回复、查询和故障消息仍然显示，电机/PID继续按原状态运行。
`telemetry status` 查询当前输出档位。`telemetry fast` 恢复原有调参 CSV 速度（当前20 Hz）；
未启用调参功能的构建则恢复原有姿态/编码器日志。输出档位不写入 NVS，重新启动恢复 slow。

调参软件连接时的 uppercase `STATUS` 会自动切换 fast，避免手动开数据流；日常查询使用 lowercase `status` 或 `mode status`。
调参过程中发送 `telemetry off/slow` 会使软件缺少预期 CSV 样本，需要调参时恢复 fast。
这些命令减少同一串口里的刷屏，不改变串口软件本身的窗口布局；固定发送框仍由电脑/手机端软件提供。

## 短时诊断：核对倾角与角速度

`diag start` 采集10秒、最高50 Hz，只改变输出，不启动/停止电机、不修改PID。结束后自动恢复当前 telemetry 档位。
`diag stop` 提前结束；`telemetry off` 也会结束诊断。诊断期间不要运行调参软件，普通8列CSV暂时停止。

第一轮在 `standby`（电机关闭）下执行 `diag start`：缓慢前倾、保持不动、缓慢后倾、再次保持不动。
将这10秒全部串口记录导出。不要重新执行 balance zero 或改变当前4/0.1/0参数。

输出有列名，行以 DIAG 开头；时间戳为MCU微秒。倾角单位度，角速度度/秒，轮速计数/秒，PWM和P/I/D项为百分比。
P/I/D是控制器分项，PWM是经过已有方向映射的实际指令；当前映射motor_sign=-1时不能直接把PWM与P+I+D按同号比较。
电机关闭时P/I/D分项为清零值，filtered_rate不代表此时的滤波测量，请用原始rate_dps核对。
平衡运行时倾角/角速度采用该次PID计算使用的输入，避免取到下一份邮箱数据；轮速仍有独立的编码器采样时间。
诊断不对角速度偏置、符号或滤波做自动校正。50 Hz采样仍不能排除更高频振动，判断原因应结合测试姿态。
